# دليل التوثيق والتشغيل: نظام تصنيف المدفوعات الخماسي الطبقات (5-Layer Payment System)
**مشروع: رواسي عدن للهندسة والمقاولات**

---

## 🎯 1. المقدمة والهدف الأساسي

تم تطوير نظام تصنيف المدفوعات الخماسي الطبقات لمشروع **"رواسي عدن للهندسة والمقاولات"** لحل مشكلة التصنيف المسطح القديم، وتقديم نموذج تصنيف متعدد الأبعاد يغطي كافة عمليات الدفع التقليدية والحديثة مع تكامل محاسبي فوري وقائي.

## 📐 2. الهيكلية خماسية الطبقات (5-Layer Classification Model)

```
┌──────────────────────────────────────────────────────────────┐
│  الطبقة 1: 🏛️ سياق الدفع (Context) — لماذا ندفع؟           │
├──────────────────────────────────────────────────────────────┤
│  • ADVANCE    → دفعة مقدمة (Advance Payment)                 │
│  • IPC        → دفعة مرحلية (Progress / IPC)                 │
│  • FINAL      → دفعة نهائية (Final Payment)                  │
│  • RETENTION  → إفراج ضمان (Retention Release)               │
│  • SERVICE    → إيراد خدمات واستشارات (Services / Consulting)│
│  • MISC       → تحصيل / صرف متنوع (Miscellaneous)            │
└──────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────┐
│  الطبقة 2: 💰 وسيلة الدفع (Instrument) — بأي أداة؟          │
├──────────────────────────────────────────────────────────────┤
│  • CASH       → نقدي (≤ 500$)                                │
│  • BANK_TRF   → تحويل بنكي (1-3 أيام)                        │
│  • CHEQUE     → شيك مصرفي (يحتاج رقم شيك + اسم بنك)           │
│  • LC         → اعتماد مستندي (للاستيراد)                    │
│  • WALLET     → محفظة رقمية (≤ 2000$)                        │
│  • IPS        → تحويل فوري (24/7)                            │
└──────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────┐
│  الطبقة 3: 🏦 القناة (Channel) — من أي جهة؟                 │
├──────────────────────────────────────────────────────────────┤
│  • CASH_BOX    → صندوق الصراف الرئيسي                        │
│  • LOCAL_BANK  → بنك محلي (التضامن، الكريمي، إلخ)            │
│  • INTL_BANK   → بنك دولي (SWIFT / البنك المركزي)            │
│  • PSP         → منصة تحصيل / كريمي باي                      │
│  • IPS_NETWORK → شبكة تحويل فوري موحدة                       │
└──────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────┐
│  الطبقة 4: ⏱️ التوقيت (Timing) — متى ندفع؟                  │
├──────────────────────────────────────────────────────────────┤
│  • IMMEDIATE   → فوري (0 أيام)                               │
│  • DEFERRED    → آجل (30 يوم)                                │
│  • SCHEDULED   → مجدول (15 يوم)                              │
│  • ON_DELIVERY → عند التسليم (On Delivery)                   │
└──────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────┐
│  الطبقة 5: 📋 المستند (Document) — بأي وثيقة؟               │
├──────────────────────────────────────────────────────────────┤
│  • MANUAL      → سند يدوي                                    │
│  • IPC_DOC     → مستخلص معتمد (Progress Certificate)         │
│  • TAX_INV     → فاتورة ضريبية رسمية                         │
│  • CERTIFICATE → شهادة دفع رسمية                             │
└──────────────────────────────────────────────────────────────┘
```

## 🗄️ 3. مخطط قاعدة البيانات (6 جداول رئيسية)

1. `payment_contexts`: تخزين السياقات المرجعية وحساباتها الافتراضية.
2. `payment_instruments`: وسائل الدفع والحدود القصوى والعمولات وأيام التصفية.
3. `payment_channels`: القنوات والمصارف والصناديق والحسابات المربوطة بدليل الحسابات.
4. `payment_timings`: خيارات التوقيت وأيام الاستحقاق الافتراضية.
5. `payment_documents`: المستندات والثبوتيات وشروط إرفاقها.
6. `payment_transactions`: الجدول الموحد الرئيسي الذي يربط الطبقات الـ 5 مع المبالغ، العمولات، الحسابات، المستخلصات، والقيد المحاسبي المزدوج.

## ⚙️ 4. القواعد المحاسبية والرقابة الوقائية

* **Deny by Default**: يرفض النظام تسجيل القيود على الحسابات التجميعية (الأب) أو غير النشطة، ويشترط استخدام الحسابات الفرعية الأخيرة المرخصة فقط (`is_posting = 1` ولا توجد لها أبناء).
* **التوازن التلقائي للقيد (Auto-Journaling)**:
  * في القبض (`IN`): `Debit` = حساب القناة (الصندوق/البنك) | `Credit` = حساب العميل/الإيراد.
  * في الصرف (`OUT`): `Debit` = حساب المورد/المصروف | `Credit` = حساب القناة (الصندوق/البنك).
  * تسجيل خط عمولة البنك مستقل في القيد إن وجدت عمولة (`fee_amount > 0`).
* **فحص الحدود القصوى (Max Limits)**:
  * يمنع الدفع النقدي `CASH` إذا تجاوز المعادل `500 USD`.
  * يمنع الدفع عبر المحافظ `WALLET` إذا تجاوز المعادل `2000 USD`.
* **التعديل وعكس القيود**:
  * لا يتم حذف أي قيد معتمد أو مرحل.
  * في حال الرفض أو الإلغاء، يتم إنشاء **قيد عكسي متزن (Reverse Journal Entry)** آلياً.

## 🔌 5. توثيق واجهات برمجة التطبيقات (API Endpoints)

### البيانات المرجعية:
* `GET /api/payments/contexts` → جلب سياقات الدفع
* `GET /api/payments/instruments` → جلب وسائل الدفع والحدود
* `GET /api/payments/channels` → جلب القنوات والحسابات
* `GET /api/payments/timings` → جلب خيارات التوقيت
* `GET /api/payments/documents` → جلب أنواع المستندات

### إدارة المعاملات:
* `POST /api/payments/transactions` → إنشاء معاملة وترحيل قيدها آلياً
* `GET /api/payments/transactions` → جلب المعاملات مع فلاتر وصفحات
* `GET /api/payments/transactions/:id` → جلب تفاصيل معاملة واحدة
* `PUT /api/payments/transactions/:id` → تعديل مسودة معاملة
* `POST /api/payments/transactions/:id/approve` → اعتماد مسودة وترحيل القيد
* `POST /api/payments/transactions/:id/clear` → تصفية ومقاصة شيك أو تحويل
* `POST /api/payments/transactions/:id/bounce` → ارتجاع شيك أو رفض تحويل مع قيد عكسي
* `POST /api/payments/transactions/:id/reverse` → عكس معاملة بالكامل مع قيد عكسي

### التقارير:
* `GET /api/reports/payments/by-context`
* `GET /api/reports/payments/by-instrument`
* `GET /api/reports/payments/by-channel`
* `GET /api/reports/payments/by-timing`
* `GET /api/reports/payments/cash-flow-forecast`
* `GET /api/reports/payments/pending-clearance`

## 🧪 6. سيناريوهات الاختبار الإلزامية الـ 10

### 1️⃣ سيناريو 1: قبض نقدي 500$ من عميل — دفعة مستخلص
* **المدخلات**: `direction: 'IN'`, `context_code: 'IPC'`, `instrument_code: 'CASH'`, `amount: 500`, `currency: 'USD'`.
* **النتيجة**: نجاح الإنشاء برقم `RCV-2026-XXXXX` وتوليد قيد:
  * مدين: الصندوق الرئيسي `$500`
  * دائن: حساب العميل / المستخلصات `$500`

### 2️⃣ سيناريو 2: تحويل بنكي 50,000$ — دفعة مقدمة
* **المدخلات**: `direction: 'IN'`, `context_code: 'ADVANCE'`, `instrument_code: 'BANK_TRF'`, `amount: 50000`, `iban: 'YE93...'`.
* **النتيجة**: نجاح العملية، وتوليد قيد متزن وتحديث رصيد الدفعة المقدمة.

### 3️⃣ سيناريو 3: شيك مؤجل 30 يوم — سداد مورد
* **المدخلات**: `direction: 'OUT'`, `context_code: 'MISC'`, `instrument_code: 'CHEQUE'`, `timing_code: 'DEFERRED'`, `cheque_no: 'CH-9941'`, `bank_name: 'بنك التضامن'`.
* **النتيجة**: ترحيل المعاملة بحالة مقاصة `pending` وإتاحة زر التصفية لاحقاً.

### 4️⃣ سيناريو 4: LC 100,000$ — استيراد مواد
* **المدخلات**: `direction: 'OUT'`, `context_code: 'MISC'`, `instrument_code: 'LC'`, `amount: 100000`, `fee_percentage: 0.50`.
* **النتيجة**: حساب العمولة الفورية `$500` وإنشاء قيد يشتمل على خط المصروفات البنكية.

### 5️⃣ سيناريو 5: محفظة رقمية 300$ — أجور عمال
* **المدخلات**: `direction: 'OUT'`, `instrument_code: 'WALLET'`, `wallet_phone: '771234567'`, `amount: 300`.
* **النتيجة**: خصم مبلغ المحفظة بنجاح وتوليد قيد الصرف.

### 6️⃣ سيناريو 6: رفض مبلغ يتجاوز max_amount
* **المدخلات**: `instrument_code: 'CASH'`, `amount: 1000 USD`.
* **النتيجة**: رفض الطلب برمز خطأ `400 Bad Request` مع الرسالة: `⛔ المبلغ المدخل تتجاوز الحد الأقصى المسموح لوسيلة الدفع [نقدي] وهو (500 USD)`.

### 7️⃣ سيناريو 7: رفض القيد على حساب أب (Deny by Default)
* **المدخلات**: `debit_account_id: 1` (حساب الأصول المتداولة التجميعي).
* **النتيجة**: رفض القيد بالرسالة: `لا يمكن تسجيل العملية على هذا الحساب، يرجى اختيار الحساب الفرعي الأخير.`

### 8️⃣ سيناريو 8: حساب العمولة تلقائياً
* **المدخلات**: `instrument_code: 'WALLET'`, `fee_percentage: 1.0%`, `amount: 1000`.
* **النتيجة**: `fee_amount = 10` و `net_amount = 1010` وتوليد خط القيد الخاص بالعمولة.

### 9️⃣ سيناريو 9: تحديث رصيد المستخلص تلقائياً
* **المدخلات**: `context_code: 'IPC'`, `context_ref_id: 1` (مستخلص بقيمة $10,000)، دفع `$4,000`.
* **النتيجة**: تحديث جدول `bills` ليصبح المسدد `$4,000` والمتبقي `$6,000` والحالة `partially_paid`.

### 🔟 سيناريو 10: تقرير توزيع المدفوعات حسب السياق
* **استدعاء API**: `GET /api/reports/payments/by-context`
* **النتيجة**: مخرجات JSON مبوبة تظهر إجمالي المقبوضات والمدفوعات لكل سياق (`ADVANCE`, `IPC`, `RETENTION`, إلخ).
